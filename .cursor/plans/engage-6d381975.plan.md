# Add 5 High-Impact Engagement Notifications

## Goal

Implement 5 engagement-boosting notifications that bring users back to the app and increase activity, using the existing trigger-based notification infrastructure.

## Selected Notifications (Quick Wins Using Existing Data)

### 1. Listing Expiring Soon (24h before expiration)

- **Trigger**: Seek listings with `expires_at` field
- **Target**: Sellers
- **Message**: "Your post '[Title]' expires in 24 hours. Renew to keep it active."
- **Impact**: Brings sellers back, prevents listing loss
- **Implementation**: Scheduled trigger (pg_cron) checking `listings.expires_at`

### 2. Rating Reminders (24h after order completion)

- **Trigger**: Orders marked completed 24h ago without ratings
- **Target**: Both buyer and seller
- **Message**: "How was your experience with [user]? Leave a rating."
- **Impact**: Increases trust scores and social proof
- **Implementation**: Scheduled trigger checking `orders.completed_at` vs `ratings` table

### 3. Unanswered Message Reminders (24h after last message)

- **Trigger**: Conversations with unread messages older than 24h
- **Target**: Recipient who hasn't responded
- **Message**: "You have an unanswered message from [sender] about '[listing]'"
- **Impact**: Increases response rates and transaction completion
- **Implementation**: Scheduled trigger checking `messages.read_at` and `conversations.last_message_at`

### 4. Payout Success Notifications

- **Trigger**: When payout status changes to 'paid' or 'completed'
- **Target**: Sellers
- **Message**: "💰 Your $[amount] payout is on the way!"
- **Impact**: Positive reinforcement, keeps sellers engaged
- **Implementation**: Real-time trigger on `payouts` UPDATE

### 5. First Sale Milestone

- **Trigger**: When seller completes their first order
- **Target**: Seller
- **Message**: "🎉 Congratulations on your first sale! You earned $[amount]"
- **Impact**: Gamification, encourages continued selling
- **Implementation**: Real-time trigger on `orders` UPDATE checking seller's order count

## Implementation Approach

### Pattern to Follow

All notifications will use the existing pattern from `DEPLOY_ALL_NOTIFICATIONS.sql`:

```sql
CREATE OR REPLACE FUNCTION notify_[event_name]()
RETURNS TRIGGER AS $$
DECLARE
    v_variable_name TYPE;
BEGIN
    -- Fetch necessary data
    -- Build notification
    INSERT INTO notifications (user_id, type, title, body, data, ...)
    VALUES (...);
    RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER [trigger_name]
AFTER INSERT/UPDATE ON [table]
FOR EACH ROW EXECUTE FUNCTION notify_[event_name]();
```

### Scheduled vs Real-Time Triggers

**Real-Time** (existing pattern):

- Payout success (#4)
- First sale milestone (#5)

**Scheduled** (new pattern using pg_cron):

- Listing expiring soon (#1)
- Rating reminders (#2)
- Unanswered message reminders (#3)

## Database Schema Analysis

Based on `databaseinfoforcontext.md`, here's what we're working with:

### Notifications Table

- `type` field has CHECK constraint with these existing types:
  - 'order_placed', 'order_confirmed', 'order_in_progress', 'order_completed', 'order_cancelled'
  - 'payment_succeeded', 'payment_failed', 'new_message'
  - 'rating_received', 'rating_reminder', 'payout_completed'
  - 'listing_interest', 'marketplace_activity'
- All needed columns already exist: `user_id`, `type`, `title`, `body`, `data`, `is_read`, `order_id`, `message_id`, `listing_id`, `related_user_id`

### Key Tables for Our Notifications

- **listings**: Has `expires_at`, `user_id`, `title`, `intent` - perfect for expiring notifications
- **orders**: Has `completed_at`, `buyer_id`, `seller_id`, `listing_id` - for rating reminders and milestones
- **ratings**: Has `order_id`, `rater_id` - to check if rating exists
- **messages**: Has `read_at`, `sender_id`, `conversation_id`, `created_at` - for unread reminders
- **conversations**: Has `last_message_at`, `buyer_id`, `seller_id`, `listing_id` - for message context
- **payouts**: Has `status`, `paid_at`, `amount_cents`, `seller_id` - for payout success
