# Development Log - January 17, 2026

## OneSignal Notification Registration Race Condition Fix

**Issue**: `TypeError: Cannot read property 'login' of undefined` when registering users for notifications

**Root Cause**: Race condition between `initializeNotifications()` (in App.tsx) and `registerUserForNotifications()` (in RootNavigator.tsx). Both were called inside `InteractionManager.runAfterInteractions()` without coordination, causing `OneSignal.login()` to be called before the SDK was fully initialized.

**Solution**: 
- Added `initializationPromise` to track in-progress initialization
- Created `ensureInitialized()` helper function
- All OneSignal-dependent functions now call `ensureInitialized()` before using the SDK
- Functions updated: `registerUserForNotifications`, `unregisterUserNotifications`, `requestNotificationPermissions`, `setupNotificationHandlers`, `getDeviceState`, `hasNotificationPermissions`, `addUserTags`, `removeUserTags`

**File Modified**: `mobile/src/services/notificationService.ts`

## Expo Go Compatibility Fix

**Issue**: `TypeError: Cannot read property 'initialize' of undefined` - OneSignal object is completely undefined in Expo Go

**Root Cause**: OneSignal requires native code that isn't available in Expo Go. The native module only exists in development builds or production builds.

**Solution**:
- Added `isOneSignalAvailable()` check to detect if native module exists
- All notification functions now gracefully exit if OneSignal isn't available
- Shows single warning log instead of repeated errors: "OneSignal not available (Expo Go)"

**Note**: Push notifications WILL work on TestFlight and App Store builds - this only affects Expo Go development testing.

## Instant Splash Screen Optimization

**Issue**: React Native splash screen was slow compared to Swift version

**Root Causes Identified**:
1. Splash image (861KB) required decoding time
2. `preventAutoHideAsync()` blocked splash until network calls completed
3. Auth initialization waited for profile verification before showing UI
4. Entrance animations on WelcomeScreen added perceivable delay
5. Splash color (#4285F4) didn't match WelcomeScreen gradient (#0A84FF)

**Solution - Instant Launch Like Instagram**:

1. **Removed splash image** - Now uses solid color only (no decode time)
   - `app.json`: Removed `image` and `resizeMode` from splash config
   
2. **Immediate splash hide** - Hide as soon as JS is ready
   - `App.tsx`: Changed from `preventAutoHideAsync()` to `hideAsync()`
   - Deferred OneSignal init with `InteractionManager.runAfterInteractions()`

3. **Non-blocking auth** - Show UI immediately, verify in background
   - `RootNavigator.tsx`: Removed loading overlay entirely
   - Profile verification runs after UI is visible
   - Notifications registered in background

4. **Instant content appearance** - No entrance animations
   - `WelcomeScreen.tsx`: All animated values start at final state (opacity: 1, scale: 1)
   - Content appears immediately on first render

5. **Color matching** - Seamless splash-to-app transition
   - Changed splash `backgroundColor` from `#4285F4` to `#0A84FF` (matches gradient start)

6. **Added expo-splash-screen plugin** for proper native handling

7. **Compressed all assets** (72-98% reduction):
   - splash-icon.png: 861KB → 240KB
   - icon.png: 861KB → 240KB
   - adaptive-icon.png: 861KB → 240KB
   - brand-icon.png: 562KB → 9KB

**Files Modified**:

- `mobile/App.tsx`
- `mobile/src/navigation/RootNavigator.tsx`
- `mobile/src/screens/auth/WelcomeScreen.tsx`

## Intermittent Splash Screen Hang Fix

**Issue**: App occasionally gets stuck on splash screen (rare, works on retry)

**Root Cause**: Race condition in splash screen hiding logic:
- `NavigationContainer.onReady` fires once when navigation is ready
- `onLayoutRootView` callback only hides splash if `loading` is false
- If `loading` is still true when `onReady` fires, splash never gets hidden
- The callback was memoized with `loading` as dependency, but `onReady` doesn't re-fire

**Solution**:
1. Created `hideSplashScreen()` helper with guard to prevent multiple calls
2. Added `navigationReady` ref to track navigation state
3. Added `useEffect` that hides splash when `loading` becomes false AND navigation is ready
4. Added 3-second failsafe timeout - splash will hide regardless of auth state
5. Renamed callback to `onNavigationReady` for clarity

**File Modified**: `mobile/src/navigation/RootNavigator.tsx`
