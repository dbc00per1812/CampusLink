## Payment & Service PIN Security Fixes

### Issue 1: "Payment Failed - Edge Function returned a non-2xx status code"

**Root Cause:** When `listing.price` is `null`, the payment flow calculated `sellerPriceCents = 0`, which caused the edge function `create_payment_intent` to reject the request with a validation error.

**Why Intermittent:** Only affected listings with null/zero prices. Fresh posts with valid prices worked correctly.

**Fix Applied:**
1. Added validation in `handleBuyNow()` to check price before showing payment sheet
2. Added safety check in `handleCardPayment()` to throw early if price is invalid
3. Removed `?? 0` fallback that was silently masking the issue

### Issue 2: Service PIN Verification Allowing Incorrect PINs

**Root Cause:** The `verifyServicePIN` function relied solely on a Supabase RPC function `verify_service_pin` which may not exist or may not properly validate PINs.

**Fix Applied:**
1. Added local PIN validation before calling RPC (defense-in-depth)
2. Fetch the actual `verification_pin` from the order and compare directly
3. Throw clear error message if PIN doesn't match
4. RPC call wrapped in try-catch to handle missing function gracefully

### Files Modified
- `mobile/src/screens/home/ListingDetailScreen.tsx` - Added price validation
- `mobile/src/services/orderService.ts` - Added local PIN verification

## Delivery Photo Upload Fix

### Issue
Order delivery confirmation photo upload was failing with "Failed to upload photo" error.

### Root Cause
The `pickDeliveryPhoto` function used `fetch().blob()` which doesn't work properly in React Native.

### Fix Applied

## OneSignal Push Notification Integration

### Overview
Integrated OneSignal push notifications for the React Native app, replacing the previous APNs-only approach.

### Issues Encountered
1. **App Group case sensitivity**: OneSignal plugin generated `group.darragh.CampusLink.onesignal` but Apple only had `group.darragh.campuslink.onesignal` registered
2. **Extension bundle ID conflict**: Apple rejected mixed-case `darragh.CampusLink.OneSignalNotificationServiceExtension`
3. **Xcode requires extension prefix match**: Extension must be prefixed with parent app bundle ID

### Solution
1. Created `patch-package` to persist OneSignal plugin modifications
2. Disabled Notification Service Extension (NSE) entirely to avoid Apple bundle ID issues
3. Basic push notifications work without NSE (just no rich media/images)

### Files Created/Modified
- `mobile/patches/onesignal-expo-plugin+2.0.3.patch` - Plugin patches
