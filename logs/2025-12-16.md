## Created Unified Header Component ✅

### Summary
Built a reusable, consistent header component that can be used across all screens in the app with a unified look: blue back arrow, centered title, and optional menu.

### Component Created

**UnifiedHeader.tsx** (`mobile/src/components/UnifiedHeader.tsx`)
- Flexible header component matching app's design system
- Blue back arrow on left (< icon)
- Centered title with optional subtitle
- Optional three-dot menu on right
- Full customization support via props
- Haptic feedback on interactions
- Consistent 56px height with proper spacing

### Features

1. **Smart Defaults**
   - Back button enabled by default with automatic navigation.goBack()
   - Clean, minimal design matching iOS standards
   - Blue accent color (#007AFF) for back arrow

2. **Customization Options**
   - Custom left/right/center components
   - Show/hide back button or menu
   - Custom onPress handlers
   - Subtitle support
   - Fully themeable

3. **Props Available**
   - `title`: Main title text (required)
   - `subtitle`: Optional subtitle
   - `showBackButton`: Show/hide back arrow (default: true)
   - `showMenu`: Show/hide three-dot menu (default: false)
   - `onBackPress`: Custom back handler
   - `onMenuPress`: Menu press handler
   - `leftComponent`: Custom left content
   - `rightComponent`: Custom right content
   - `centerComponent`: Custom center content

### Usage Examples

**Basic Header:**
```tsx
<UnifiedHeader title="Order Details" />
```

**Header with Menu:**
```tsx
<UnifiedHeader 
  title="Chat" 
  showMenu={true}
  onMenuPress={() => showOptions()}
/>
```

**Header with Subtitle:**
```tsx
<UnifiedHeader 
  title="Abhi D" 
  subtitle="Active now"
/>
```

### Documentation
Created comprehensive usage guide: `UnifiedHeader.usage.md`
- Multiple usage examples
- Integration with React Navigation
- Props reference table
- Screen-specific examples

### Integration
- Exported from `components/index.ts`
- Ready to use: `import { UnifiedHeader } from '../../components'`
- Works with SafeAreaView for proper iPhone notch handling
- Can replace React Navigation's default headers

### Architecture

**Flow:**
1. **Mobile App**: OneSignal SDK initializes on app start
2. **User Login**: Sets external user ID, gets player ID
3. **Database**: Player ID saved to `user_notification_preferences` table
4. **Backend**: Edge function sends notification via OneSignal REST API
5. **OneSignal**: Routes to APNs (iOS) or FCM (Android)
6. **Device**: Notification delivered and displayed
7. **User Taps**: Navigation handled via custom data payload

### Database Integration

**Table: `user_notification_preferences`**
- `push_token`: Now stores OneSignal Player ID
- `push_platform`: Stores 'ios' or 'android'
- `push_enabled`: Controls notification delivery
- No schema changes required

### Navigation Support

Notifications support deep linking to:
- **Orders**: `{ order_id: 'uuid' }` → OrderDetail screen
- **Chats**: `{ conversation_id: 'uuid' }` → Chat screen
- **Listings**: `{ listing_id: 'uuid' }` → ListingDetail screen
- **Generic**: `{ screen: 'ScreenName', params: {...} }` → Any screen

### Key Features

1. **Unified Platform**: Single SDK for iOS & Android
2. **User Targeting**: External user IDs for precise targeting
3. **Rich Notifications**: Images, badges, sounds, custom data
