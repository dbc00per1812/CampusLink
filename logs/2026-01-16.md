## Fixed Order Archiving Logic

Fixed listings not being archived after seller accepts an order. The previous implementation had two issues:

### Issues Fixed

1. **Wrong timing**: Archiving was happening in `createOrder` (buyer action) instead of `acceptOrder` (seller action)
2. **Silent failures**: Supabase errors were not being caught properly - the code used try/catch but Supabase returns errors in the response object, not by throwing
3. **RLS violation**: Buyer was trying to update seller's listing, which fails due to Row Level Security policies

### Changes Made

**orderService.ts**
- Removed archive logic from `createOrder()` - listings stay visible until seller commits
- Added archive logic to `acceptOrder()` with proper error handling
  - Seller now archives their own listing (RLS compliant)
  - Uses `eq('user_id', currentUserId)` to ensure ownership
- Fixed `cancelOrder()` unarchive error handling - properly destructures and checks Supabase error response
- Fixed `deletePendingOrder()` unarchive error handling - same pattern

### Behavior Now
- Listing remains visible when buyer creates order (pending payment)
- Listing is archived when **seller accepts** the order
- Listing is unarchived if order is cancelled (and no other active orders exist)
