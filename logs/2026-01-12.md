# 2026-01-12 - Wallet Pending Balance Fix

## Issue: Wallet Shows $0 Despite Completed Transactions

### Problem
After a transaction completed (buyer confirmed delivery, payment captured), the seller's in-app wallet showed nearly $0 even though funds were successfully captured in Stripe. The seller was confused thinking their payment was lost.

### Root Cause
The wallet UI was only displaying the `available` balance from Stripe Connect. However, Stripe has a **payout delay** (typically 2-7 business days) where funds first land in `pending` before becoming `available`.

- **Available balance**: Funds that can be paid out immediately
- **Pending balance**: Funds captured but waiting for Stripe's clearing period

The wallet was showing `available: $0.01` (from an older cleared transaction) but the 50 cents from the recent transaction was in `pending`.

### Solution
Updated WalletScreen to prominently display pending funds:

1. Changed "In Escrow" to "Pending" in the balance card
2. Updated total to show `available + pending`
3. Added a green banner when pending funds exist explaining the 2-7 day clearing period

### Files Modified

#### 1. `WalletScreen.tsx`
- Updated `WalletBalance` interface to remove unused `escrow` field
- Changed balance stat from "In Escrow" to "Pending" with appropriate icon
- Updated total calculation: `available + pending` instead of `available + escrow`
- Added pending funds banner with message: "{amount} is on the way! Funds typically become available in 2-7 business days."

#### 2. `walletService.ts`
- Cleaned up `getWalletBalance()` to remove `escrow: 0` return value

### Before/After

**Before:**
- Available Balance: $0.01
- In Escrow: $0.00
- Total: $0.01
- *(User thinks payment was lost)*

**After:**
- Available Balance: $0.01
- Pending: $0.50
- Total: $0.51
- Banner: "$0.50 is on the way! Funds typically become available in 2-7 business days."
- *(User understands funds are clearing)*

## Issue 2: Deferred Onboarding - Sellers Can't Receive Payments Without Stripe Setup

### Problem
If a seller hasn't completed Stripe Connect onboarding, funds were captured to the platform account but:
1. No tracking of which funds belong to which seller
2. No automatic transfer when seller completes onboarding
3. Seller sees $0 in wallet with no explanation

### Solution: Full Deferred Onboarding Support

#### 1. New Database Table (`docs/sql/pending_seller_payouts.sql`)
Created `pending_seller_payouts` table to track funds held for sellers:
- `seller_id`, `order_id`, `amount_cents`, `payment_intent_id`
- `status`: pending → transferred/failed
- `transfer_id`: Stripe transfer ID once transferred

#### 2. Updated `capture_payment/index.ts`
After capturing payment, checks if destination charges were used:
- If YES: Seller received funds directly via Stripe Connect
- If NO: Records pending payout in `pending_seller_payouts` table

#### 3. Updated `stripe-webhook/index.ts`
Enhanced `account.updated` handler:
- When seller completes onboarding (`transfers: active` + `payouts_enabled: true`)
- Fetches all pending payouts for that seller
- Creates Stripe transfers to send funds to their Connect account
- Marks pending payouts as transferred

#### 4. Updated `walletService.ts`
- Added `getPendingSellerPayouts()` to fetch pending onboarding funds
- Updated `getWalletBalance()` to include `pendingOnboarding` amount

#### 5. Updated `WalletScreen.tsx`
- Added `pendingOnboarding` to balance state
- Updated Total calculation to include all pending funds
- Added orange banner for pending onboarding: "You have $X waiting! Complete payout setup to receive your earnings. Funds may take up to 7 days to become available after setup."

### Seller Experience After Fix

**Before Stripe Setup:**
- Seller can list and sell items ✅
- Payment is captured successfully ✅
- Wallet shows: "You have $X waiting! Complete payout setup..."
- Funds tracked in `pending_seller_payouts` table

**After Completing Stripe Setup:**
- Webhook detects onboarding complete
- Automatically transfers all pending funds to seller's Connect account
- Funds appear in "Pending" (2-7 day Stripe clearing period)
- Eventually becomes "Available" for payout

### Deployment Required
1. Run SQL in Supabase: `docs/sql/pending_seller_payouts.sql`
2. Redeploy `capture_payment` edge function
3. Redeploy `stripe-webhook` edge function

## Issue 3: Listings Not Archiving/Unarchiving on Order Accept/Cancel

### Problem
Listings should be automatically archived when a seller accepts an order (to prevent other buyers from purchasing the same item), and unarchived if the order is cancelled.

### Root Cause
The `acceptOrder()` and `cancelOrder()` functions in the React Native order service did not include any listing archive/unarchive logic.

### Solution

#### 1. Added `unarchiveListing()` to `listingService.ts`
New function to set `archived: false` on a listing, making it available again.

#### 2. Updated `acceptOrder()` in `orderService.ts`
After updating order status to `in_progress`, now archives the listing:
```typescript
await supabase
  .from('listings')
  .update({ archived: true })
  .eq('id', order.listing_id);
```

#### 3. Updated `cancelOrder()` in `orderService.ts`
- Expanded cancellation window: now allows cancelling orders in both `placed` AND `in_progress` status
- After refunding buyer, unarchives the listing:
```typescript
await supabase
  .from('listings')
  .update({ archived: false })
  .eq('id', order.listing_id);
```

### Order Flow After Fix

1. **Buyer places order** → Order status: `placed`, Listing: active
2. **Seller accepts** → Order status: `in_progress`, Listing: **archived**
3. **If cancelled** → Order status: `cancelled`, Listing: **unarchived** (available again)
4. **If completed** → Listing stays archived (item sold)

### Files Modified
- `mobile/src/services/listingService.ts` - Added `unarchiveListing()`
- `mobile/src/services/orderService.ts` - Archive on accept, unarchive on cancel
